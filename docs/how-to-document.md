# 11. How to document

| Situation                                                                   | Use                   | Notes                                                                                                                                                                                             |
| --------------------------------------------------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| You made a choice that's expensive to reverse and people will later ask why | ADR                   | Covers one decision: context, options considered, decision, consequences. Once accepted it isn't edited; a new ADR supersedes it instead.                                                         |
| You're working something out and want feedback before choosing              | RFC / design doc      | It looks forward and is open for comment. If it ends in a big decision, write an ADR for that decision afterward.                                                                                 |
| You're building something and need to say how it works                      | Tech spec             | Interfaces, data flow, edge cases. It changes as the code changes, unlike an ADR.                                                                                                                 |
| On-call or a repeated ops task                                              | Runbook               | Steps only. No history, no reasoning.                                                                                                                                                             |
| A rule everyone (people and agents) should follow                           | Standard / convention | Coding style, naming, MR rules. For agents this goes in AGENTS.md.                                                                                                                                |
| A small decision that isn't worth an ADR                                    | Decision log entry    | One line in a shared log: date, decision, who, link. Use it for decisions an ADR review rejects as not significant enough.                                                                        |
| You're explaining a system to a newcomer                                    | README / overview     | What it is, how to run it, where things are.                                                                                                                                                      |
| Terms keep getting mixed up                                                 | Glossary              | Write down the team's ubiquitous language: one meaning per term, used the same way in conversation, code, docs, and prompts. Saves you explaining "skill" vs "workflow" vs "agent" over and over. |

Docs live in the repo next to the code, so agents can read them and keep them current.
